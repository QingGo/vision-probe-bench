# DeepSeek V4-Flash-Vision-Exp vs 小米 MiMo-V2.5：多模态能力实测对比（89 题 × 3 种配置）

> 本文是一份**可复现的实测报告**：用程序化生成的 89 道带标准答案的视觉探针，在"默认 / 最大思考 / 多模态 Agent"三种配置下，对比 DeepSeek `deepseek-v4-flash-vision-exp` 与小米 `mimo-v2.5` 的感知、推理与 Agent 能力。总测试成本不到 3 元人民币，全部代码与数据可复现。

---

## 一、背景：为什么测这两家

2026 年，多模态 API 的价格战打得非常凶。

- **DeepSeek** 发布了实验性视觉模型 `deepseek-v4-flash-vision-exp`：视觉输入按 token 计费，价格与文本模型一致（输入 1.5 元/百万 token 起，输出 4.5 元起，空闲时段），单张图片最多折算 384 个 token。
- **小米 MiMo** 发布 `mimo-v2.5`：原生全模态模型（图像/视频/音频/文本），输入 1 元/百万 token、输出 2 元/百万 token，图片按实际分辨率换算 token。

两者都兼容 OpenAI API，都在卷"便宜 + 多模态"。但便宜不等于好用。DeepSeek 官方还给出了"多模态 Agent 能力接近 Opus-4.8"的评测数据（ApexBench 36.5 vs 39.4、ZeroBench 35 vs 34、Chartography 64.3 vs 65.0），而纯视觉能力并没有公布完整榜单——这本身就值得玩味。

我的问题是三个：

1. 纯多模态感知，谁更强？
2. 开最大档思考（DeepSeek 论文《Thinking with Visual Primitives》声称迷宫/路径追踪领先 17 分），结果如何？
3. 和 Agent 工具环路结合，DeepSeek 的能力会被放大吗？

## 二、测评方法：合成探针 + 三配置矩阵

### 2.1 为什么用合成探针

真实基准（MMMU、DocVQA、ChartQA 等）存在两个问题：一是前沿模型已刷到 90%+，区分度低；二是下载量大、判分复杂。合成探针用 PIL/matplotlib 程序化生成，**答案在生成时就是已知的（Ground Truth）**，判分完全自动化，无版权问题，可精确复现。

### 2.2 三个探针集（共 89 题）

| 探针集 | 题数 | 覆盖能力 |
|---|---|---|
| 基础探针 | 61 | 中文/英文小字号 OCR、场景文字、密集表格、拥挤柱状图、计数、空间推理、多图对比、图中数学、细粒度符号、分辨率 A/B |
| 进阶探针 | 20 | 迷宫导航、路径追踪、多跳空间推理、密集重叠计数、ARC 风格网格推理 |
| Agent 探针 | 8 | UI 截图→点击工具、表单→submit 工具、校验纠错循环、图表→查询工具 |

### 2.3 三种配置

| 配置 | 说明 |
|---|---|
| 默认 | thinking 按各家默认开启，max_tokens=1024 |
| 最大思考 | `thinking.enabled` + `reasoning_effort=max`，max_tokens=65536（MiMo 思考无档位，enabled 即最强） |
| Agent 环路 | 看图→调工具→看结果→再调，最多 6 轮；think / nothink 各跑一遍 |

### 2.4 判分方式

- 转录类：字符级 Levenshtein 准确率（忽略空白）
- 问答类：精确匹配 / 数值容差（±0.01）/ 网格字母序列比对
- Agent 类：最终答案 + 工具调用参数是否与 GT 一致

### 2.5 公平性控制

同一张图、同一 prompt 发给两家；max_tokens 拉满避免思考截断；thinking 档位显式控制；记录每次调用的 token、耗时、成本。

## 三、结果一：纯感知（61 题，默认配置）

| 任务 | deepseek-v4-flash-vision-exp | mimo-v2.5 |
|---|---|---|
| 中文小字号 OCR | **0%** (0/4) | **100%** (4/4) |
| 英文小字号 OCR | 29% | 98% |
| 细粒度数学符号 | 89% | 100% |
| 场景文字（彩底旋转） | 100% | 100% |
| 密集表格提取 | 100% | 100% |
| 计数（13~77 个点） | 100% | 100% |
| 空间推理 3×3 | 100% | 100% |
| 多图对比 | 100% | 100% |
| 图中数学 | 100% | 100% |
| 拥挤柱状图（22 类） | 17% | 17% |
| **整体平均** | **69%** | **85%** |
| 全对题数 | 42/61 | 51/61 |
| 成本 | 0.089 元 | 0.042 元 |

> 注：本轮 max_tokens=1024，DeepSeek 有若干题因思考 token 耗尽返回空串，对其不利；后续轮次已修正。

**最大差距在中文 OCR**。同样的中文句子（"北方的冬天格外寒冷，清晨的湖面结满厚冰"），MiMo 逐字正确；DeepSeek 直接**幻觉**成完全无关的内容："语言库 语料库 语言资源 语料库语言学"。英文随机字符串也出现典型的重复模式幻觉："LU LUU LUUU LUUUU..."。

## 四、结果二：分辨率 A/B——两家架构的分水岭

把同一张图分别以高清版和缩小版（宽 700px）发送，看各家对分辨率的利用：

| 图像 | deepseek 高清−缩小 | mimo 高清−缩小 |
|---|---|---|
| 中文文本 | 0 − 0 | **1.0 − 0** |
| 拥挤图表 | 0 − 0 | **1.0 − 0** |
| 英文随机串 | 0 − 0 | 0.03 − 0 |

结论非常清晰：

- **DeepSeek 喂高清图没有任何收益**：其视觉编码器在进入模型前会把图缩到约 800×800 当量（单图封顶 384 token），再高的输入分辨率也留不住细节。
- **MiMo 吃满分辨率**：按实际分辨率换算 token（≈像素/1024），缩图后立即从 1.0 掉到 0。

这是两家纯感知差距的**根本原因**——不是模型智能差，而是 DeepSeek 选择了激进的视觉压缩路线（论文自述 7000 倍压缩率），代价就是细节丢失。

## 五、结果三：最大思考下的进阶探针（20 题）

既然 DeepSeek 论文《Thinking with Visual Primitives》声称在迷宫导航（66.9% vs GPT-5.4 的 50.6%）和路径追踪上领先，我们就专门构造了这些任务，并把思考档位开到最大：

| 任务 | deepseek (max think) | mimo (max think) |
|---|---|---|
| 迷宫（可解性/最短路径） | **2/3** | 1/3 |
| 路径追踪（同色交叉曲线） | **2/3** | 1/3 |
| 多跳空间推理 | 5/5 | 5/5 |
| 密集重叠计数 | 0/3 | **2/3** |
| ARC 风格网格推理 | 0/6 | 0/6 |
| **整体** | **45%** | **45%** |
| 成本 | **1.45 元** | **0.10 元** |

三个发现：

1. **论文的强项是真的**：max 思考下 DeepSeek 在迷宫、路径追踪上反超 MiMo——拓扑推理优势在 API 模型上兑现了（一道路径题花了 28,864 个思考 token 才答对）。
2. **但代价是 14 倍成本**：max 思考动不动烧掉 2~5 万 token（单题最贵 0.24 元），而 MiMo 思考很轻（单题 0.005 元左右）。不用思考时（上一节），DeepSeek 全面落后。
3. **ARC 两家全挂**：即便 DeepSeek 在"颜色替换"这类最简单规则上思考了 51,076 个 token 仍然答错——粗粒度网格的视觉感知瓶颈，两家都没跨过去。

## 六、结果四：多模态 Agent 环路（8 题）

最后验证核心问题：**Agent 工具环路能否放大 DeepSeek 的多模态能力**（官方"接近 Opus-4.8"的说法）。工具：`get_value(类别)`、`click(按钮)`、`submit(姓名,电话,邮箱)`、`verify(数值)`。

| 任务 | deepseek | mimo |
|---|---|---|
| UI 截图→点击工具 | 2/2 | 2/2 |
| 表单→submit 工具 | 2/2 | 2/2 |
| 校验纠错循环 | 1/1 | 1/1 |
| 图表→查询工具（难） | 1/3 | 1/3 |
| **整体（think 与 nothink 结果完全一致）** | **75%** | **75%** |

结论：**Agent 放大对两家是等价的**。

- 在"看图→动作"类任务上，两家都接近满分——Agent 框架确实有用。
- 但在感知瓶颈任务（4.5pt 小标签读不出）上，工具环路**零放大**：纯感知 1/3，带上 `get_value` 工具还是 1/3。DeepSeek 甚至烧了 72 次工具调用仍失败——工具返回"无此类别"救不了读不出的字。
- 开最大思考跑 Agent 环路，结果逐题完全相同。

**对官方数据的解读**：DeepSeek"接近 Opus-4.8"更可能来自其本来就强的**文本 Agent 骨干**（官方表格中 DeepSWE 59.3 已超 Opus-4.8 的 58.0），加上官方 Agent 基准的输入是**可读的**截图/图表。放大来自"强文本 Agent + 可读输入"，而非"视觉感知被放大"。

## 七、结论与选型建议

| 场景 | 推荐 | 理由 |
|---|---|---|
| 中文/小字号 OCR、高分辨率细节图 | MiMo-V2.5 | 100% vs 0%，吃满分辨率 |
| 批量低成本视觉处理 | MiMo-V2.5 | 单图更省，nothink 下能力更强 |
| 迷宫/路径/拓扑推理 | DeepSeek（max 思考） | 唯一反超场景，但成本贵 14 倍 |
| 多模态 Agent（UI/表单/工具） | 打平，选便宜的 | 两家都是 75% |
| ARC 类抽象推理 | 都不要 | 两家 0 分 |

一句话总结：**MiMo 赢在感知，DeepSeek 赢在思考，Agent 场景打平；DeepSeek 的强项只在 max 思考下成立，且价格是 MiMo 的 14 倍。**

## 八、局限性与可复现性

局限性：

- 以合成数据为主，未跑 MMMU-Pro / DocVQA 等真实基准（模块 B 未实施）。
- 每题单次采样，存在运行间方差（例如迷宫"是否可达"在三轮中 是/否 翻转），结论应看整体趋势而非单题。
- API 模型是实验版本，随时可能更新。

工程复现：项目将开源（`vision-bench`），包含探针生成器（`gen_images.py`/`gen_adv.py`/`gen_agent.py`）、评测器（`bench.py`/`agent_bench.py`）、全部图片与逐题结果。支持 50 线程并发、断点续跑、每题即时写盘。全部 89 题 × 多配置的总 API 成本不到 3 元。
