# 深度求索发布 DeepSeek V4.1 Flash 的中间版本内测，该模型体验如何？

> 先说结论：这是一次**针对性的感知修补**，但修补的准确位置和我想的大不一样。我把 v4.1 和老版 `deepseek-v4-flash-vision-exp`、小米 `mimo-v2.5` 放在同一套自建探针评测上（61 感知 + 20 推理 + 8 Agent），并把关键的"单点结论"全部升级为 N=5 采样复核。最终画像：**v4.1 修好的是"画布形状鲁棒性"（超宽扁画布不再幻觉），而不是"OCR 能力从 0 到 1"；坐标输出的坑找到了确切的因果机制（声明尺寸直接决定了像素映射），可以 100% 掌握；推理强项（多跳）保持满分，但抽象推理（ARC）两家都稳定全挂，且 max 思考档贵到离谱；"计数 13~77 点"的 75% 是采样波动，不是稳定的能力退步。**

---

## 一、它是什么？为什么要测

`deepseek-v4.1-flash-expires-on-0910` 是 DeepSeek 官方放出的中间版本内测模型（ID 带 `expires-on-0910` 截止日期，内测 9 月 10 日截止）。它延续 V4-Flash 架构 + 视觉模块（DeepSeek-ViT patch 14×14 + MLP aligner），并叠加了《Thinking with Visual Primitives》论文里的"视觉原语"能力（box/point/polygon 坐标记号）。

老版 `flash-vision-exp` 有两个已知短处：**中文小字 OCR 直接幻觉**（本该读"北方的冬天格外寒冷"，它读成"语言库 语料库 语言资源"）；**视觉原语依赖显式触发**。我测 v4.1 的核心问题就两个：它修了什么？修到什么程度？

## 二、怎么测的：合成探针 + 采样纪律

沿用此前的评测框架（已开源，`QingGo/vision-probe-bench`）：图片与答案全部程序化生成，判分全自动。

### 2.1 三组探针

| 探针集 | 数量 | 覆盖能力 |
|---|---|---|
| 感知探针 | 61 题 | 中/英文小字号 OCR、场景文字、密集表格、拥挤图表、计数、空间推理、多图对比、图中数学、细粒度符号、分辨率 A/B |
| 推理探针 | 20 题 | 迷宫可解性与最短路径、同色交叉曲线追踪、多跳空间方向推理、密集重叠计数、ARC 风格网格变换 |
| Agent 探针 | 8 题 | UI 点击、表单提交、数值校验纠错、图表数据查询（工具环路） |

### 2.2 配置与公平性

- **档位**：非思考（`thinking.type=disabled`）与最大思考（`reasoning_effort=max`）两档；Agent 另测 think/nothink。
- **公平**：三家同图同 prompt；max_tokens 拉满（65536）；同档位比。
- **判分**：OCR 用字符级 Levenshtein 准确率；答案类精确匹配/数值容差；ARC 用网格字母序列比对；Agent 用最终答案 + 工具参数。

### 2.3 两条本次"从开头就遵守"的纪律（都是上一轮踩坑的产物）

1. **缩放档意识**：官方文档明确，图片进模型前会被自动缩放（总像素 <384×384 的保持长宽比放大；大于约 800×800 当量的缩小）。所有测试图都标注"设计尺寸"与"缩放档位"两类信息——**模型实际看到的画布 ≠ 你渲染的画布**。
2. **采样本数**：关键结论一律 ≥3 次（多数取 5 次）采样并报告分布。单次采样方差大到能翻转结论（同一道迷宫题三次采样 0%、0%、100%）。

## 三、能力总表：它修了什么

### 3.1 感知：61 题，三项重要修正后的画像

| 任务 | 老版 flash-vision | **v4.1-flash** | mimo-v2.5 |
|---|---|---|---|
| 中文小字号 OCR | 0%（超宽扁画布下） | **100%** | 100% |
| 英文小字号 OCR（字符级） | 29% | **99%** | 98% |
| 细粒度符号 | 89% | **100%** | 100% |
| 密集表格提取 | 100% | 100% | 100% |
| 场景文字 | 100% | 100% | 100% |
| 计数（13~77 点） | 100% | 75%（6/8，N=5 复核后震荡，见附 C） | 100% |
| 空间推理 / 多图 / 数学 | 100% | 100%（数学 3/4） | 100% |
| 拥挤柱状图（22 类小标签） | 17% | 17% | 17% |
| **整体（字符加权平均）** | **69%** | **79%** | **85%** |

表面看是"中文 OCR 从 0% 到 100%"。但如果你就停在这，会得出一个错误结论。**关键对照实验如下**。

### 3.2 画布对照实验：老版的 OCR 不是"0"，是"挑画布"

同样的中文句子，两种画布（同一模型、同一 prompt、N=5）：

| 画布 | v4.1 | 老版 |
|---|---|---|
| 1900×64（超宽扁条，宽高比 30:1） | **1.00 ×5** | **0.00 ×5**（稳定幻觉） |
| 1500×120（标准横画布） | **1.00 ×5** | **1.00 ×5**（满分） |

**这是整个评测里最有信息量的一个实验**。老版的中文 OCR 能力本身并非 0——换成标准画布立刻满分。老版的病是**"超宽扁画布鲁棒性缺失"**：遇到 30:1 的异形画布，它会脑补"这张图是旋转/翻转过的"（真实回答里写着"图片上下翻转了""左右翻转后逆时针旋转了90度"），然后在错误前提上幻觉。

所以 v4.1 修复的本质是**画布形状鲁棒性**：OCR 引擎没变强，变强的是"对任意布局都不慌"。同源证据：把老版幻觉的原始输出和 v4.1 的满分输出同图比对，后者是纯文本转录，前者是"翻转+幻觉"组合——差的不是识别，是构图理解。

### 3.3 分辨率敏感性（修正后的 A/B）

我最初用"高清 vs 缩至 700px"做 A/B 得到"v4.1 吃满高清"结论——但事后审计发现那组实验**画布和缩放档同时变化**（1900×64 vs 700×23 都在放大档）。修正版重测：**同画布 1500×120、同不缩放档、只变源分辨率**（13px 清晰渲 vs 6px 渲染后放大 4×，N=5）：

| 画布同为 1500×120，源不同 | v4.1 | 老版 |
|---|---|---|
| 高清源 | **1.00** | **1.00** |
| 低清源 | 0.63 | **0.79** |

- **分辨率敏感性是真的，但与"服务端缩放"无关**——同画布下仅变源分辨率，两版都从 1.00 掉到 0.63~0.79。
- **老版抗低清反而比 v4.1 更稳**（0.79 vs 0.63）。这与 3.2 一脉相承：老版的感知引擎不弱，弱的是对异常构图（超宽扁条）的优雅处理。

### 3.4 推理：20 题，强项稳，但 arc 全挂 + 贵

| 任务 | 老版 | **v4.1** | MiMo |
|---|---|---|---|
| 迷宫（3 题） | 2/3 | 1/3 | 1/3 |
| 路径追踪（3 题） | 2/3 | 2/3 | 1/3 |
| 多跳空间推理（5 题） | 5/5 | 5/5 | 5/5 |
| 密集重叠计数（3 题） | 0/3 | 0/3 | 2/3 |
| ARC 网格（6 题） | 0/6 | 0/6 | 0/6 |
| **合计** | **45%** | **40%** | **45%** |

- **多跳空间推理三家全满分**——这是所有模型共有的强项，v4.1 并未放大。
- **ARC 是稳定能力缺口，不是采样运气**：N=5 复核后 v4.1 与老版在 6 题 × 5 次 = 60 次中**0 次成功**（色块替换、镜像、旋转这类"最简单变换"）。一题上它烧掉 5.3 万思考 token 也照样错。
- **迷宫结论不可靠**：maze_yes v4.1=1.00×5 稳定对，maze_no 却"历史对过、N=5 全错"，maze_steps=0×5 稳定错。迷宫这类"是/否"题采样方差大到能翻转结论，任何单次结果都别信。
- **成本是硬伤**：20 题 max 思考 v4.1 花了 **1.79 元**（老版 1.45 元、MiMo 0.10 元），且有一题把 65,536 token 用尽直接截断返回空答案——max 思考档又贵又容易"思考到死"。

### 3.5 Agent：8 题，三家一模一样

| 任务 | 老版 | v4.1 | MiMo |
|---|---|---|---|
| UI 点击 / 表单提交 / 校验纠错 | 2/2 | 2/2 | 2/2 |
| 图表查询（3 题） | 1/3 | 1/3 | 1/3 |
| **合计** | **6/8** | **6/8** | **6/8** |

工具环路能把"可读信息"类任务放大到满分，但 4.5pt 小标签读不出时，工具反馈"无此类别"也救不了——**感知瓶颈是 Agents 的尽头**。

## 四、视觉原语：能被触发，且有四道明确的坑

### 4.1 触发与格式

| 测试 | 结果 |
|---|---|
| 密集计数 + box（显式要求） | ✅ 完整 `<｜ref｜>…<｜/ref｜><｜box｜>[[x1,y1,x2,y2]]<｜/box｜>` 出现在思考链 |
| 路径追踪 + point | ✅ `<｜point｜>[[x,y]]<｜/point｜>` 逐步出现在思考链 |
| polygon | ✅ `<｜polygon｜>...` 可用 |
| 自然描述（不触发） | ❌ 全程零原语 |

**必须显式触发**，与你独立调研的结论一致。另外两个实现细节：坐标输出是**像素值**（论文说的 0–999 归一化在 API 上没兑现）；格式示例 `x1,y1,x2,y2` 可能被原样输出、全角/半角 `<｜point｜>`/`<|point|>` 混出——解析代码要兼容。

### 4.2 坐标坑的根因：输出坐标 = 归一化坐标 × 声明尺寸

（这一节是全文最长的因果链，值得细看。）

**第一层证据（缩放控制）**：同一条路径图，以三个尺寸发过去，模型自己报的"画面尺寸"：

| 档位 | 真值尺寸 | 模型报的尺寸 | 起点(真值) | 输出 |
|---|---|---|---|---|
| 400×350（**放大档**） | 400×350 | **512×384**（幻觉） | (50,300) | (57,300) |
| 600×525（**不缩放**） | 600×525 | 600×500（正确） | (75,450) | (75,440) |
| 1600×1400（**缩小档**） | 1600×1400 | **1920×1800**（幻觉） | (200,1200) | (180,1620) |

**第二层证据（3 档 × 2 模式矩阵，36 个随机点）**：prompt 里告知真实尺寸 vs 不告知：

| 档位 | 告知尺寸 | 不告知尺寸 |
|---|---|---|
| 300×300（放大档） | **2.4px** | 131px（崩） |
| 600×500（不缩放） | **1.8px** | 2.0px（照样准） |
| 1600×1400（缩小档） | **3.8px** | 340px（崩） |

**第三层证据（纯文本对照）**：完全不诱导原语，只输出 `(x, y)`——精度几乎无差异（41 是 1.7~9.6px 级，老版 7.7~15.1px 级）。**坐标精度不是原语格式带来的**。

**第四层证据（错误尺寸声明，因果闭环）**：还是那张 1600×1400 的 6 点图，故意声明错误尺寸：

| 声明 | 理论预测 | v4.1 实测（红点，真值 798,1046） | 平均误差 |
|---|---|---|---|
| 1600×1400（正确） | 无偏 | (799,1053) | **4.6px** |
| 800×700（半尺寸） | 输出 = 真值 × 0.5 | **(400,525)** | 563px |
| 3200×2800（双倍） | 输出 = 真值 × 2.0 | **(1600,2141)** | 1138px |

**半尺寸臂输出精确等于真值×0.5，双倍臂精确等于真值×2.0，每一点都如此**。这不是巧合——**v4.1 的内部视觉坐标是归一化的，像素输出 = 归一化坐标 × prompt 声明的尺寸**。声明缩小它就输出真值一半的像素值，声明放大就输出双倍。

第四层证据解释了前面所有现象：告知正确尺寸 → 精确像素映射（2~4px 级）；不告知 → 模型拿自己幻觉的画布尺寸做乘法（131/340px 崩）；而且模型"报尺寸"本就不可信（缩放档下它报 1000×98、1920×1800 这类幻觉值，4 次实验无一次正确）。

**老版则完全是另一副面孔**：正确尺寸声明臂都有 **505px 平均误差**（接近随机），双倍臂两次采样输出还不一致（1494 vs 1575）——**老版的"画布换算回路"根本没接上线**，不是感知差，是整套映射机制缺失。

**操作结论（坐标的最佳实践）**：① 图片控制在"不缩放波段"（边长约 390~800px）；② prompt 里显式声明真实尺寸。两条都做 = 2~4px 准心精度；缺任何一条，随时偏出半张图——**与是否用原语无关**。

### 4.3 诱导原语三臂：普通任务不会变好，反而更差

既然原语"能被诱导"，那要求它先在普通题里用 box/point 标注再回答，会更好吗？16 题 × 3 种 prompt × 2 采样：

| 臂 | prompt 策略 | v4.1 整体 |
|---|---|---|
| A 基线 | 原版问题 | 0.434 |
| B 详细提示 | 同样长度的"请逐步分析"，**无原语** | **0.561** |
| C 诱导原语 | 强制输出 `<｜ref｜>/<｜box｜>/<｜point｜>` + 声明尺寸 | 0.405 |

- **诱导原语不提升普通任务**（C-A 多为 0 或负；迷宫 no −0.5、路径 −0.2~−0.5、密集计数无提升）。唯一正增益"图表找最高"（+0.5）靠的是"先标注目标柱"的提示工程，不是原语机制。
- **B 详细提示 > 一切**：把步骤说清楚、不带原语，收益最大。
- **诱导是负资产**：C 臂 completion 3976 token（A 3594）、空回答率 **37.5%**（A 25%）——"先标注后回答"拉长思考链，更易耗干预算返回空。
- 原语价值在自己受训的领域（拓扑/定位）**才兑现**，跨任务不泛化；与论文自述"依赖显式触发、跨场景泛化有限"吻合。

## 五、选型与操作：这张表 + 四条纪律

| 场景 | 推荐 | 理由 |
|---|---|---|
| 中文/小字 OCR、截图、UI、图表感知 | ✅ v4.1 可放心用 | 任意画布不幻觉（老版挑画布） |
| 低成本批量视觉处理 | ✅ v4.1 非思考档 | 61 题仅 0.03 元，与 flash 同价 |
| 精确坐标/结构化输出 | ⚠️ 预处理 + 后处理 | 声明尺寸 + 不缩放档；与原语无关 |
| 多跳空间推理 / 多图比较 | ✅ 三家都好 | 全满分，v4.1 性价比最高之一 |
| 复杂抽象推理（ARC 类） | ❌ 三家稳挂 | N=5×60 次 0 分 |
| 高并发 max 思考 | ❌ 贵且易截断 | 20 题 1.79 元，已见 65K 截断 |

**四条实践纪律**：
1. 视觉定位：图处理到 390~800px + prompt 声明真实像素尺寸（必要时用文件 API 保留原图）；
2. 坐标解析：兼容全/半角 `<｜point｜>`/`<|point|>`、防格式示例 `x1,y1,x2,y2` 混入输出；
3. 复测任何"模型退化/变好"前，先排除 prompt/ max_tokens 配置污染（本评测就差点因此误判 v4.1 OCR 从 1.0 掉到 0——配置改了"只输出文字本身"约束和截断上限，全是假象）；
4. 结论别信单次采样：迷宫 is/否 能翻转、ARC 60 次 0 分才敢叫"稳定缺"。

**一句话总结**：v4.1 是"感知修补版"——修好画布鲁棒性，OCR/清晰度对任意排版都稳；原语可用但别指望泛化，坐标坑可 100% 规避（声明尺寸是金钥匙）；推理上它最强的是多跳，最弱的是抽象，最大风险是思考档太贵。

### B. 修正版重测：核心结论全部不变

5 类图各生成"强制不缩放"版本（OCR 重绘 1500×120；迷宫/符号贴白边至 384/385；计数缩至 795；图表缩至 1272×427），同配置重跑：OCR 1.0=1.0 / 计数 0.33=0.33 / 图表 0=0 / 符号 1.0=1.0——**只变画布、结论零漂移**；迷宫因采样方差存疑（见 C）。

### D. 两个想用被否掉的工具

- **图像 token 反推缩放档——不可行**。token 数与尺寸强相关、与内容无关（同图 resize 与不同内容同尺寸的数据完全吻合），但存在反例：121,600px→219 token vs 147,456px→185 token——**总像素更小却更多 token**（短边存在 185 平台 + 长条额外代价），不遵守"总像素单向规则"，不可反推。
- **模型自报尺寸——不可信**。缩放档下 4 次实验报出 1000×98、1000×50、1920×1800 等值，无一正确。
