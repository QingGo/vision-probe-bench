# 深度求索发布 DeepSeek V4.1 Flash 的中间版本内测，该模型体验如何？

> 先说结论：这不是一次换代，而是一次**有效的感知修补**。我把它和老版 `deepseek-v4-flash-vision-exp`、小米 `mimo-v2.5` 放在同一套自建评测上跑（61 道感知探针 + 20 道推理探针 + 8 道 Agent 探针），并复现验证了它的"视觉原语"能力。体验结论：**看清晰的问题修好了，看复杂的问题依旧，坐标输出有明确的可规避的坑。**

---

## 一、它是谁？测试背景

`deepseek-v4.1-flash-expires-on-0910` 是 DeepSeek 官方新放出的中间版本内测模型（ID 带 `expires-on-0910` 截止日期）。从公开资料看，它延续了 V4-Flash 架构 + 视觉模块的路线：DeepSeek-ViT（patch 14×14）+ MLP aligner，叠加 DeepSeek《Thinking with Visual Primitives》论文里的"视觉原语"能力（输入推理链中的 box/point 坐标记号）。

我为什么测它？因为老版 `flash-vision-exp` 存在两个已知问题：感知细节差（中文 OCR 直接幻觉）、视觉原语依赖显式触发。我想知道中间版本是否修补了这些问题，以及修补到了什么程度。

## 二、实验方法：一套可复现的"探针"评测

我基于此前开发的评测框架（`vision-probe-bench`，已开源），用程序化生成的**合成探针**测。所谓探针，就是图片和正确答案都由代码生成，判分全自动，不依赖人工标注。

### 2.1 三组探针

| 探针集 | 数量 | 覆盖能力 |
|---|---|---|
| 感知探针 | 61 题 | 中文/英文小字号 OCR、场景文字、密集表格、拥挤图表、计数、空间推理、多图对比、图中数学、细粒度符号、分辨率 A/B（同一张图高清 vs 缩至 700px） |
| 推理探针 | 20 题 | 迷宫可解性与最短路径、同色交叉曲线路径追踪、多跳空间方向推理、密集重叠计数、ARC 风格网格变换 |
| Agent 探针 | 8 题 | UI 截图→按钮点击工具、表单→结构化提交工具、数值校验纠错循环、图表→数据查询工具 |

### 2.2 配置与控制

- **档位**：非思考（`thinking.type=disabled`）与最大思考（`reasoning_effort=max`，兼容映射到 max）两档；Agent 测试另测 think/nothink 各一次。
- **公平性**：三家（v4.1 / 老版 flash-vision / MiMo）用同一张图、同一条 prompt；max_tokens 拉满（65536）避免思考截断；同档位对比。
- **判分**：OCR 用字符级 Levenshtein 准确率；答案类用精确匹配/数值容差（±0.01）；ARC 用网格字母序列比对；Agent 用最终答案＋工具参数比对。
- **成本记录**：每次调用记录 prompt/completion/reasoning token 与耗时，按官方公开价格折算。

### 2.3 视觉原语专项测试

按官方论文（box/point/polygon 原语）构造 4 个任务：密集计数+box、路径追踪+point、polygon 输出、自然描述（不触发）。另做 1 组**坐标缩放控制实验**（详见第四节）。

## 三、实验结果

### 3.1 感知：中文 OCR 从 0% 修到 100%

61 道感知探针（非思考档）：

| 任务 | 老版 flash-vision | **v4.1-flash（新）** | mimo-v2.5 |
|---|---|---|---|
| 中文小字号 OCR | 0% | **100%** | 100% |
| 英文小字号 OCR（字符级） | 29% | **99%** | 98% |
| 细粒度符号 | 89% | **100%** | 100% |
| 密集表格提取 | 100% | 100% | 100% |
| 场景文字 | 100% | 100% | 100% |
| 计数（13~77 点） | 100% | 75%（6/8） | 100% |
| 空间推理 / 多图 / 数学 | 100% | 100%（数学 3/4） | 100% |
| 拥挤柱状图（22 类小标签） | 17% | 17% | 17% |
| **整体（字符加权平均）** | **69%** | **79%** | **85%** |

老版最致命的问题是中文 OCR 整句幻觉（"北方的冬天格外寒冷，清晨的湖面结满厚冰"读取成"语言库 语料库 语言资源"），v4.1 修好了这个病。英文随机字符串也从"LU LUU LUUU"式重复幻觉，变成接近完美的逐字转录。

遗留短板：拥挤柱状图两家都 17%——4.5pt 的小标签谁都读不动；计数从 100% 略降到 75%，可能与小图缩放有关（见 3.3）。

### 3.2 分辨率 A/B：修复的机制验证

同一张图，高清版与缩小版（宽 700px）各发一次：

| 测试 | 高清 | 缩至700px |
|---|---|---|
| 中文文本 | **1.0** | 0 |
| 英文随机串 | 0.03 | 0 |
| 拥挤图表 | 0 | 0 |

中文文本高清直接满分、缩小后归零——v4.1 **吃满了高分辨率**（这点更像 MiMo 而非老版 flash-vision，后者高清/缩小无差异）。它修复的是"感知分辨率"问题。

### 3.3 推理：20 道进阶题，强项没放大，贵且会截断

| 任务 | 老版 | **v4.1** | MiMo |
|---|---|---|---|
| 迷宫（3 题） | 2/3 | 1/3 | 1/3 |
| 路径追踪（3 题） | 2/3 | 2/3 | 1/3 |
| 多跳空间推理（5 题） | 5/5 | 5/5 | 5/5 |
| 密集重叠计数（3 题） | 0/3 | 0/3 | 2/3 |
| ARC 网格（6 题） | 0/6 | 0/6 | 0/6 |
| **合计** | **45%** | **40%** | **45%** |

最大问题在成本：20 题 max 思考 v4.1 花了 **1.79 元**（老版 1.45 元、MiMo 0.10 元），其中一题把 65,536 token 额度用尽直接截断（`finish_reason=length`）返回空答案——**max 思考下它是最贵又最容易"思考到死"的**。

ARC 题（色块替换、镜像、旋转这类最简单变换）三家依然全挂，即使 v4.1 在其中一题上烧掉 5.3 万思考 token。

### 3.4 Agent：多模态 Agent 放大依旧有限

| 任务 | 老版 | v4.1 | MiMo |
|---|---|---|---|
| UI 点击（2 题） | 2/2 | 2/2 | 2/2 |
| 表单提交（2 题） | 2/2 | 2/2 | 2/2 |
| 校验纠错（1 题） | 1/1 | 1/1 | 1/1 |
| 图表查询（3 题） | 1/3 | 1/3 | 1/3 |
| **合计** | **6/8** | **6/8** | **6/8** |

**三家完全一样**。工具环路（get_value/click/submit/verify）能把 UI、表单这类"可读信息"任务放大到满分，但读不出的小标签（4.5pt）依旧读不出——工具反馈"无此类别"救不了感知瓶颈。

### 3.5 视觉原语：真的能用，但需要显式触发

| 测试 | 结果 |
|---|---|
| 密集计数 + box（显式要求） | ✅ reasoning 与回答均出现完整 `<｜ref｜>…<｜/ref｜><｜box｜>[[x1,y1,x2,y2]]<｜/box｜>` 序列 |
| 路径追踪 + point | ✅ `<｜point｜>[[x,y]]<｜/point｜>` 逐步出现在思考链 |
| polygon | ✅ `<｜polygon｜>[[x1,y1,x2,y2,x3,y3]]<｜/polygon｜>` 可用 |
| 自然描述（不触发） | ❌ 全程零原语，纯文字 |

**必须显式触发**——这与你独立调研的结论一致。

## 四、坐标精度到底如何？一个 3 档 × 2 模式矩阵实验

坐标不准是视觉原语最大的槽点。我先做了个**缩放控制实验**验证机制：官方文档写明图片进入模型前会被自动缩放（总像素 <~384×384 的放大，更大的缩小到约 800×800 当量）。把同一张路径图分别以三个尺寸发过去：

| 档位 | 真值尺寸 | 模型报的尺寸 | 起点(真值) | 输出 |
|---|---|---|---|---|
| 400×350（会被**放大**） | 400×350 | **512×384** | (50,300) | (57,300) |
| 600×525（**不缩放**） | 600×525 | 600×500 | (75,450) | (75,440) |
| 1600×1400（会被**缩小**） | 1600×1400 | **1920×1800** | (200,1200) | (180,1620) |

规律初步成型：**只有不触发缩放的中间档，模型才报得出正确尺寸**。一旦触发缩放，它就开始"猜"画面尺寸（512×384、1920×1800 都是幻觉值），坐标随之整体偏移。

为了把因果钉死，我做了第二轮**矩阵实验**：3 个尺寸档位（300×300 放大档 / 600×500 不缩放档 / 1600×1400 缩小档）× 每张 6 个随机位置的彩色圆点 × 两种提问方式（**prompt 里告知真实尺寸** vs **不告知**），共 36 个随机坐标点，逐点算欧氏误差（px）：

| 档位 | 告知尺寸 | 不告知尺寸 |
|---|---|---|
| 300×300（会被放大） | **2.4px** ✓ | 131px ✗ |
| 600×500（不缩放） | **1.8px** ✓ | 2.0px ✓ |
| 1600×1400（会被缩小） | **3.8px** ✓ | 340px ✗ |

**结果非常干净**：

1. **模型本身的定位能力很强**：只要 prompt 里声明了真实尺寸，三个档位全部误差 2~4px（红色圆点半径就有十几像素，几乎是准心精度）。
2. **坐标错位的唯一真凶是"尺寸认知断开"**：不缩放档位无论告知与否都准（2px 级）；一旦进入缩放档（小图被放大、大图被缩小），不告知尺寸时误差直接爆炸到 **131 / 340px**——因为模型不知道原始画布有多大，只能自己脑补。
3. **操作结论**：用视觉原语拿坐标，务必同时满足两条——① 图片控制在"不缩放波段"（边长约 390~800px）；② prompt 里显式声明图片尺寸（如"图片尺寸是 600×500 像素"）。两者都做到，精度就是 2~4px 量级；缺任何一个，随时可能偏出半张图。

另外两个解析注意点：坐标是**像素值**（官方论文说的 0–999 归一化在 API 上没兑现）；模型还会把格式示例 `x1,y1,x2,y2` 原样吐出来、且全角/半角 `<｜point｜>` 与 `<|point|>` 都会出现，解析代码要做兼容。

## 五、选型与场景结论

| 场景 | 推荐 | 理由 |
|---|---|---|
| 中文/小字 OCR、截图、UI、图表感知 | ✅ v4.1 可放心用 | 中文 OCR 100%，吃满分辨率 |
| 低成本批量视觉处理 | ✅ v4.1（非思考档） | 61 题仅 0.03 元，与 flash 同价 |
| 需要精确坐标/结构化输出 | ⚠️ 需预处理+后处理 | 缩放档位不对会整体偏移 |
| 复杂视觉推理（ARC 类） | ❌ 三家都不行 | 0/6 |
| 高并发 max 思考 | ❌ 贵且易截断 | 20 题 1.79 元，已见 65K 截断 |

**一句话总结**：v4.1-flash 是"flash-vision 的感知修补版"——**看得到的东西变清楚了，看不到的东西（高密度细节、抽象推理）依旧看不到**。想用它做低成本多模态基线，值得一试；想用它做精确视觉定位，请先按第四节做好尺寸预处理。

## 附：局限性与复现

- 全部为合成探针（答案已知、无版权、可自动判分），未跑 MMMU-Pro / DocVQA 等公开基准（后续可补充）。
- 每题默认单次采样，存在运行间方差（如计数题 6/8 上下浮动），结论看趋势。
- 模型为内测版本，随时可能更新或下线；文中 API Key 均已轮换，代码通过环境变量读取，仓库无敏感信息。
- 复现：项目 `QingGo/vision-probe-bench`（GitHub），含探针生成器、评测器、视觉原语与缩放验证脚本，支持 50 线程并发与断点续跑。
